# 到期管家

## 当前版本 2.5.2

- 修复系统语言与 Scripting 的单独应用语言不一致时，小组件误用应用语言的问题。现在优先读取 `Device.systemLanguageTag`／`systemLanguageCode`；旧版运行环境才使用 `Device.preferredLanguages` 后备。
- 小号左上角图标语义名称以及所有尺寸的日期、内置标题、分区、空状态和错误提示使用同一系统语言来源。英文系统中的 `doc.text.magnifyingglass` 显示为 “Tax & Accounting”，不再显示“税务会计”。
- 本次不修改事项数据、布局、字号、行高、点击区域、容量或通知逻辑。

### 2.5.1

- 修复通知在语言变化时被全部撤销却只能补回少量的问题：已有有效通知按项保留，替换成功再撤旧。真正时刻变化优先修复已有排程；查询及提交时重新检查时钟，不把过去时间计作未来通知。
- 主数据损坏时显示独立恢复页；确认恢复前隔离保留原始数据，保全失败不写入。未知更高格式只允许导出检查，不覆盖。可导出原始数据与恢复档案；它不是普通可直接导入的备份。
- 原样恢复备份后，符合条件的手动完成仍可撤销；旧长 ID、关联通知开关和空白 Apple 提醒历史可正常备份恢复，拒绝破坏版本递增的异常数字。
- 提醒已完成后的缓存读写失败只显示警告，缓存日期按当前时区重算。组件「检查操作」打开结果详情；主界面新增「上次组件操作」，确认清除只移除所查看事件的提示。

- 小型组件的具体时间放在原有备注行右侧，右上角仍只显示日期；无具体时间不增加内容，标题和预告的位置保持不变。
- 新增「记录与数据安全」：最近 100 次完成、手动完成安全撤销、最近 10 份本机快照，以及文件备份导出／恢复。恢复会保留恢复前快照，通知偏好恢复后先关闭通知，请检查后重新开启。Apple 提醒的恢复请使用系统 App。
- 「通知与提醒」默认关闭：通知时刻、真实到期日再次提醒和单项开关。仅处理手动事项，未来 90 天滚动排程，最多 40 个提醒计划，组件每次普通新增或文案更新最多 3 条，已有提醒的时刻修复最多 40 条。逐条替换可能短暂多出 1 个替换副本，宿主总请求保守限制 60；无余量或接口失败会保留旧请求并明确报未完成。需要后续运行续排，实际横幅取决于系统权限和调度。
- 更新入口先展示当前／最新版本与更新内容，安装前备份，拒绝降级；同步失败显示上次成功时间和重试指引。数据保存成功后的刷新失败只作为警告。
- 超过 1,000 条事项不再静默截断。提前日从零点开始处理；未提前的定时事项按真正截止时刻进入待处理。

本地快照不是独立异地备份，建议导出到可信位置；备份含事项名称、金额、备注、完成记录和设置。自动化测试不能替代 iPhone 真机视觉与实际通知验收。

一款为 [Scripting](https://apps.apple.com/us/app/scripting/id6479691128) 编写的 iPhone 桌面组件，用来统一跟踪信用卡账单、订阅、周期账单、一次性截止日期和 Apple 提醒事项。

## 已实现

- 小、中、大组件按 Apple 公布的 iPhone WidgetKit 尺寸和实际 `Widget.displaySize` 分别排版，并使用系统语义色与完整的系统容器背景。
- 小号组件优先展示当前最紧急事项。当前事项图标是完成按钮：可见图标为 17 pt，点击热区为 40 pt；文字区域仍负责打开详情。
- 小号主体标题按实际可用宽度动态选择 16/15/14 pt，分别适配一、二、三行，最多显示三行。2.3.4 去掉左上角重复图标，仅显示当前图标的本地化语义名称；右上角显示当前事项的明确日期。2.3.6 将 13 pt 金额或备注恢复为左对齐；过长时仍使用中间省略。下一事项预告继续使用固定槽位，有无内容时都不跳动。小组件内容左右各内收 3 pt，预告上方不绘制分隔线。
- 中号组件每行以事项类别图标作为完成按钮：可见图标为 17 pt，点击热区仍为 38 pt；标题最多两行，点文字打开详情。标题根据 `Widget.displaySize.width` 和中英文字符的视觉宽度预估换行：预计两行时字号由 14 pt 降为 13 pt，极长标题再降一级。中号按实际高度动态显示 2–3 项，事项之间不再绘制分隔线，保留 1 pt 自然间距。只读或来自缓存的事项不能完成，其图标会变灰，右侧保留明确日期与锁定或缓存标识。
- 大号组件采用类似系统「提醒事项」的层级和空间节奏：顶部首项显示日期日号、月份以及事项分类；Apple 提醒事项则显示其 Reminders List，右上角放置 26 pt 的摘要图标。常见大号的顶部摘要区高 74 pt，分隔线下移到该区域底部，仍是全组件唯一的分隔线。
- 大号的每个事项行以 18 pt 类别图标作为完成按钮，点击热区仍为 40 pt；顶部摘要图标保持 26 pt。
- 大号按实际 `Widget.displaySize` 分档，并根据当前真正使用的一或两个分区动态计算行高：250 pt 高显示 3 项，281 pt 高显示 4 项，320/354/382 pt 高显示 5 项。标题同时根据 `Widget.displaySize.width` 和中英文字符的视觉宽度预估换行：预计两行时字号由 15 pt 降为 14 pt，极长标题再降一级。常见高度最多使用本地化的两组分区，较矮大号合并为一组；底部多余空间会分配回顶部与行距，使上下间距和四周留白更均衡。大号不绘制逐行分隔线；标题最多两行，点文字打开详情，完成后由队列中的后续事项补入空位。只读或缓存项同样以灰色图标以及右侧锁定或缓存标识区分。
- 所有小、中、大及锁屏附件组件共用一套系统语言判断。内置标题、图标语义名称、月份、日期、分区、空状态和错误提示优先按 `Device.systemLanguageTag`／`systemLanguageCode` 使用简体中文、繁体中文或英文；旧版 Scripting 才退回 `Device.preferredLanguages`。其他系统语言以英文文案兜底。
- 所有组件均不再显示相对天数或实时倒计时。列表行和小号预告只显示明确日期，避免“2 天后”等文案与日期重复。
- 中、大号右侧金额或备注保持固定单行槽位和 116/124 pt 宽度；2.3.6 保持原有长文本优化不变：先允许系统轻微收紧字距，最低字号比例为 85%，仍放不下时从中间省略，以保留名称开头及卡号、套餐编号等尾部信息。该策略不会挤压左侧标题或改变组件容量。
- 2.4.0 将手动周期事项的间隔改为数字输入，可为按天、周、月、年重复分别填写 1–99 的任意正整数，不再受 1–12 菜单限制；月末、31 日和闰日锚点规则继续生效。
- 2.4.2 使用原生 `LabeledContent` 固定显示数字行左侧的「间隔」和「提前提醒」，并将提前设置收进同一个「重复」卡片，不再单独显示「提前提醒」分组。间隔值右侧会根据当前周期动态显示天、周、个月或年，使「间隔 3 个月」之类的设置无需依赖下方说明即可理解。此次更新只改善编辑页的分组与标签，不改变已有事项、周期计算、提前行动日或存储 schema。
- 每个手动事项可单独填写 0–365 天的「提前天数」，0 表示不提前。提前天数只生成更早的行动日：从行动日零点开始，事项会进入主脚本的「需要处理」分区并提前参与排序，组件也会把行动日及真实到期时刻纳入刷新安排。真实到期日不会被改写，仍作为周期推进锚点及组件显示日期；仅填写提前天数不会发出通知，需要另行开启「通知与提醒」。
- 完成控件使用交互式 `Button + AppIntent`。完成成功后请求刷新时间线，并由后续事项补位；实际内容变化时机由 WidgetKit 控制，不使用、也不声称使用 Apple 私有的点击瞬时动画。
- 手动事项提供 11 种到期类型：信用卡、订阅会员、账单缴费、贷款分期、保险保单、数字服务、证件合同、保养维护、预约日程、纪念日期和其他事项。类型菜单、存储校验、默认图标、颜色和同时到期的排序均由同一份定义生成。
- 内置 130 个本机 SF Symbols，并按财务、影音娱乐、工作效率、数字服务、社交通讯、居家生活、健康运动、出行旅行、学习阅读、创作设计和其他 11 个 App Store 常见方向分组；编辑事项时可手动覆盖，升级后仍兼容已经保存的旧图标。
- 根据名称离线匹配更多订阅品牌与类别，包括 AI、影音、音乐、游戏、新闻阅读、设计创作、办公效率、云服务、安全、购物、餐饮、健康、教育和出行等方向。匹配时优先采用较长、较具体的短语，并收窄容易误判的通用关键词。
- 2.0 将导入的 Apple 提醒事项图标识别扩展为“事项标题 → 精确 List 分类 → List 中的品牌或产品短语 → 备注 → 默认值”。内置 126 个 List 图标方向和 1,100+ 个简体、繁体及英文精确别名，系统化覆盖工作效率、财务账单、订阅到期、数字服务、影音通讯、购物物流、居家生活、健康运动、交通旅行、学习阅读和创作设计。Emoji、全角字符以及 `List / Tasks / Reminders / 清单 / 列表 / 事项 / 提醒` 后缀均可规范化；分类仍采用完整名称匹配，不会把 `workshop` 误判为 Work 或把 `Deliverance` 误判为 Delivery。标题中的明确品牌或具体事项始终优先于 List 分类。
- 图标匹配完全离线，不查询 App Store、品牌图标库或其他网络服务，事项名称、List 与备注不会因匹配图标而上传。缓存只保存推断出的图标提示，不保存 Apple 提醒事项的备注正文。
- 小号组件显示最紧急的 1 件；中号动态显示 2–3 件；大号按实际高度显示 3–5 件，典型的 250/281/320/354/382 pt 高分别显示 3/4/5/5/5 件。
- 完成当前事项后，新出现的下一件可立即继续点击；旧时间线中的控件仍会由代次校验拒绝，避免重复完成同一期事项。
- 后续事项在固定槽位中自动补入；同一天有具体时间的事项按时间先后排列。
- 完成按钮带有本期识别码，重复点击或旧组件快照不会把周期事项误推进两期。
- 手动周期事项完成一次只推进一期；一次性事项完成后移入「已完成或隐藏」。
- Apple 提醒事项可直接从组件标记完成；系统周期提醒的下一次实例由 iOS 生成。只读列表中的事项不能从组件完成，在中、大号中会以灰色类别图标和右侧锁定标识注明。
- Apple 提醒事项默认读取全部列表，也可在主脚本中按一个或多个具体列表筛选；同名列表会显示所属账户以便区分。若所选筛选范围已失效或暂时无法读取，原有筛选设置不会被错误覆盖。
- Apple 提醒事项在小号组件中将所属列表名称显示在中间备注栏；手动事项的金额和备注使用同一位置。
- 提醒事项读取失败时最多回退到 24 小时内、且筛选范围完全相同的成功快照；缓存行会明确标记且不可从组件完成。实时读取已经成功但快照写入失败时，会单独提示缓存保存失败，不会把实时数据误报成读取失败。提醒事项快照继续使用 schema v1，新版新增的派生图标提示为兼容字段，旧快照可直接读取并在缺少提示时重新推断。
- 支持一次性、每 N 天、每 N 周、每 N 月和每 N 年；N 可自定义为 1–99，并保留月末和闰日规则。
- 在 Scripting 内直接新增、编辑、删除和完成事项，无需修改代码；若旧编辑页打开后同一事项已在别处更新，保存或删除会提示冲突，避免旧内容覆盖新数据。
- 事项保存在 Scripting 的本机共享 `Storage` 域，不会被打进远程安装包；首次运行 1.2.1 或更高版本会自动迁移旧版私有数据，后续替换脚本包无需重新录入。2.4.0 可兼容读取 schema v1/v2 状态，缺少新字段的旧事项会安全采用「提前 0 天」，下次保存时写为 schema v3。提醒事项快照继续使用独立的 schema v1。无法识别 schema v3 的旧脚本会拒绝覆盖数据，避免降级破坏新字段。
- 保存后会等待存储落盘，再优先刷新用户小组件，避免必须删除并重新添加组件才能看到新数据。

## 安装要求

- iOS 17 或更高版本（交互式桌面组件要求）。
- Scripting 2.4.9 或更高版本（直接完成 Apple 提醒事项使用 `Reminder.get`）。

安装步骤：

1. 在 iPhone 上打开上方固定安装链接，确认更新或导入「到期管家」。从 1.2.0 升级时不要先删除已有脚本。
2. 更新后运行一次主脚本；1.2.1 或更高版本会自动迁移已有事项并刷新用户小组件。2.4.0 会兼容载入 schema v1/v2 数据，并在下一次保存时升级为 schema v3。全新安装时再添加手动事项。
3. 如需合并 Apple 提醒事项，打开对应开关并完成授权。随后可进入「提醒事项列表」选择全部列表或一个/多个具体列表。首次打开列表选择页会申请日历与提醒事项权限；权限必须在可见的主脚本内授予，桌面组件无法弹出授权框。
4. 长按 iPhone 主屏幕，添加 Scripting 组件。
5. 长按新组件 →「编辑小组件」→ 选择「到期管家」。
6. 分别在真实主屏幕上检查你使用的小、中或大号版式。

以后更新时可继续使用同一个链接，也可运行主脚本后在底部版本信息旁点击「检查并更新版本」；启用远程资源后，Scripting 还会按自己的调度检查固定地址。无需保存不同版本的 `.scripting` 文件。

## 使用方式

- 小号点当前事项图标可完成当前一期；中、大号点事项类别图标完成。三种尺寸均可点文字打开事项详情。
- 新事项默认使用「自动匹配」图标；在编辑页点「图标」可固定为任意内置语义图标，再改名称也不会被自动替换。
- 周期事项的「间隔」可输入 1–99 的正整数，并在「重复」卡片的输入行左侧固定显示「间隔」；右侧会按所选周期动态显示天、周、个月或年。例如选择按月并填写 3，输入行会直接显示为「间隔 3 个月」。
- 「提前天数」也在同一个「重复」卡片中，可按事项填写 0–365。行动日到达后，事项会进入「需要处理」并提前排序，但组件和事项详情仍显示真实到期日，后续周期也继续按真实到期日的锚点推进。
- 对手动周期事项，组件完成一次只推进一个周期，不会静默跳过累计逾期记录。
- 对 Apple 提醒事项，组件会直接把系统提醒标记为完成；若它是重复提醒，下一次出现时间由 iOS 控制。
- 完成按钮只记录「本期已处理」。它不会自动付款、续订、取消订阅或操作银行账户。
- 设备锁定时，iOS 可能要求先解锁才能执行交互。
- 可在主脚本中预览三种尺寸，并手动请求刷新桌面组件。

## iOS 刷新限制

桌面组件不是常驻进程。脚本会在下一个本地午夜、最近的具体行动或到期时刻、开启系统提醒事项后的约每 3 小时，或用户交互时请求新数据；行动日因此可以驱动「需要处理」状态和队列重排，但最终执行时间仍由 WidgetKit 决定，可能延后。

2.3.4 起组件不再使用动态 `DateLabel` 显示实时或天数倒计时，只显示明确日期与具体时刻。2.5.0 可为手动事项开启本地通知；系统提醒事项仍由 Apple 提醒事项管理通知。本地通知采用有上限的滚动排程，需要后续运行补充，实际显示时间受系统权限、专注模式、通知摘要和调度影响，不能承诺准点横幅或永久后台运行。

完成操作由 `Button + AppIntent` 提交；按钮触发后脚本会请求刷新，但图标、圆圈和队列何时变化仍由 WidgetKit 交付新时间线的时机决定。本脚本没有使用 Apple 私有能力，也不提供或声称提供系统「提醒事项」那种点击瞬时动画。

手动事项的具体时间按设备本地时钟保存；跨时区旅行时会保持相同墙钟时间。系统提醒事项的具体时间则按其绝对时刻换算为设备当前时区。

共享 `Storage` 只保存在本机，但不是密码保险箱，同一 Scripting 中的其他脚本理论上也能访问共享域。请勿填写完整卡号、密码等秘密；事项标题和金额也可能直接显示在锁屏可见的主屏幕组件上。
