# v2.5.5 回归与验收

## 自动化验证

- 标题中的品牌或明确事项必须始终优先于 List 和备注。
- 具体 List 分类及 List 名中的品牌或产品信息必须优先于任何备注提示。
- 高置信度备注中的品牌、产品或明确类别可以覆盖 `Tasks`、`Inbox`、`Personal`、`Reminders` 等通用 List。
- 普通动作备注不得覆盖任何已命中的 List；只有 List 完全未命中时才能提供图标。
- 标题、List 与备注必须独立匹配；例如将 `Amazon`、`Prime`、`Video` 分放在三个字段中不得组合成流媒体图标。
- `Cardinal Setup`、`Gift Card Setup`、`SIM Card Setup`、`Venture Capital Review`、`Wallet Planning Workshop` 等相近无关文字继续保持负例保护。
- 快照只允许保存白名单图标提示及 `strong`／`ordinary` 置信度；序列化结果不得包含备注正文、命中关键词或文本片段。非法图标提示必须丢弃。
- 没有置信度字段的旧快照必须继续读取，并按保守优先级处理；一次成功的主脚本实时同步后应写入新的置信度。
- 系统语言、日期、本地化图标名称、通知排程、组件布局、容量与完成点击区域的既有回归测试必须保持通过。
- 发布前运行完整测试、TypeScript 检查、安装包解压比对与云端发布检查。

## iPhone 待验收

1. 更新到 2.5.5 后运行一次主脚本，确认 Apple 提醒事项实时读取成功，再等待 WidgetKit 刷新。
2. 建立泛化标题与通用 List 的提醒，在备注中填写一个词库支持的明确品牌或产品，例如 `1Password Families`；确认小、中、大组件显示对应图标。
3. 将相同备注放入一个明确分类的 List，例如 Music 或 Delivery；确认具体 List 保持优先，不被备注覆盖。
4. 在通用 List 中只填写“周末完成”“稍后处理”等含糊备注，确认不会产生错误类别图标；在没有匹配 List 时验证受支持的普通动作备注可以提供后备图标。
5. 核对标题优先场景、旧提醒事项、离线缓存回退及重新联网后的图标均一致；无需删除或重新添加事项和组件。
6. 核对小、中、大及锁屏组件的排版、系统语言、日期、完成操作与通知设置均未变化。

自动化测试不能替代 WidgetKit 真机刷新、原生排版、动画、VoiceOver 或真实通知送达验证。
