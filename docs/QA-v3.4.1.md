## 改动及故障边界

3.4.0 把系统提醒内容链接改为 Scripting 运行入口，再调用外部系统详情 URL。此前模拟测试验证了参数和回调，但没有验证 iPhone 上的原生传参及最终选中详情。本次不把第二次外部跳转当作阅读备注的前提：新 `reminder-notes` 与旧 `open-reminder` 链接均先呈现独立备注页，页面可见后按原 ID 读取。

左上角保持当前事项，下一项预告保持下一项；完成仍用原 AppIntent，与读取备注独立。主题标签增加矩形内容点击形状、24 pt 最小高度。主界面提供明确的备注查找入口，不在参数缺失时擅自选择当前第一项或其他事项。

不能仅凭源码确定用户设备是在原生 Link 交付、运行参数还是外部打开阶段停止；本次没有声称在 iPhone 复现并确认根因。若升级刷新后仍只到主界面，需进一步采集设备上的目标交付情况，备用入口不等于原生点击已验收。

## 自动化覆盖

328 项测试（19 个文件）在香港、UTC、纽约三个时区全部通过，其中新增 14 项备注读取／页面／入口回归测试。TypeScript 7.0.2 严格类型检查及 `git diff --check` 通过。

- 准确 ID、允许的 UUID 别名、512 字符边界、非 UUID 账户、无效与错配 ID；不显示其他事项的备注。
- 完整长备注、原始换行、空备注、已完成／只读事项；仅调用读取，不保存或完成，不打开备注内的 URL。
- 权限失败、已删除／不可用、10 秒超时；不将原生错误中的私密信息写入诊断，迟到结果不写缓存。
- 首屏先加载，后显示完整正文；保留全文、不设行数上限，按内容纵向展开。使用原生 Text／List，不依赖未文档化的选中文本属性。
- 页面重试、切换 ID、关闭页面后失效回调；不闪现前一事项正文。
- 外部打开只能由按钮显式触发，再次查验 ID，快速双击只发起一次；失败保留备注页，不跳到首页。
- 新／旧运行参数直接进入独立页面，不加载主应用或启动维护；普通启动、手动编辑及原完成流程仍通过原回归测试。
- 备用列表遵循现有列表筛选／日期范围，按标题或列表名称本机搜索，显示缓存说明并在点击时实时读取备注。空列表与失败可以重试，不预读各项备注。
- 备注模块不使用 Storage、备份写入、网络请求或日志；URL 只传动作和 ID。

## 原生验收清单

1. 更新原脚本并运行、刷新组件。点小号左上角主题：应看到「提醒事项备注」页以及当前项的准确标题、列表和全文，而非主设置页。
2. 点标题／日期／下一项预告，以及中／大号内容：核对各自对应事项；左侧图标仍只完成本期，不打开备注。
3. 在系统提醒事项里修改备注，点「重新读取备注」应显示更新；空备注、长段落、空行、深浅色、大字和 VoiceOver 均需真机检查。
4. 点击已完成提醒的旧链接仍可只读查看；删除后明确提示。关闭权限或断开账户时提示权限／不可用，不更改事项。
5. 点击「在提醒事项中打开」确认当前 iOS／账户下的实际详情定位；此私有 URL 能被接受不代表系统一定显示正确详情。
6. 若原生小组件仍只启动主界面，可用「系统提醒事项 → 查看提醒事项备注」明确选择原项，并反馈点击结果以继续定位宿主传参问题。

本机 JSX／原生 API 模拟测试不等同于 iPhone WidgetKit 点击、原生排版、权限弹窗及详情定位验收。此环境没有可控制的用户 iPhone，也没有读取其真实备注或执行真实完成。

## 接口依据

- [Scripting Script](https://scriptingapp.github.io/guide/Script/Script)：运行链接及 queryParameters。
- [Scripting Link](https://scriptingapp.github.io/guide/Views/Link)：URL 点击入口；文档指出使用 Link 时 widgetURL 会被忽略，因此不添加冲突的全局备用 URL。
- [Scripting Reminder](https://scriptingapp.github.io/TestFlight/guide/Changelog/2.4.9/)：按标识读取提醒。
- [Text View Modifiers](https://scriptingapp.github.io/guide/View%20Modifiers/Text%20View%20Modifiers)：文本换行与行数控制。
- [Apple 小组件场景链接](https://developer.apple.com/documentation/WidgetKit/Linking-to-specific-app-scenes-from-your-widget-or-Live-Activity)：宿主接收原生点击 URL 的流程。
