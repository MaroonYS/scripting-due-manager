日期：2026-10-03。本轮审查启动、状态读写、显示排序、前后台刷新、提醒列表读取、完成及通知维护，实施有证据的热路径和生命周期改进。没有重置数据、改用网络账户服务或重写已接受的原生写入流程。

## 架构与边界

- 新 `src/due_ordering.ts` 只依赖日期及类型，每项一次状态、一次行动日期投影，再按 stale、紧急度、行动时间、截止时间、优先级、中文标题、来源与 ID 排序；保留完全相同键的稳定性，临时数组不持久化。`reminders.ts` 重导出旧 API。
- `manual_item_groups.ts` 不再依赖 storage、Reminders 或图标库，不构造金额／备注／图标展示对象，用相同排序器及同一时间分组，返回原对象，保留隐藏顺序与旧重复 ID first-match。主列表共用一次来源隔离 Map 和时间，刷新计时直接读启用事项日期，不解析图标。
- `storage.ts` 普通编辑、设置、删除、完成、撤销及完成历史提交前比较最新正常化内容，快照后再比较共享原文；同毫秒不同内容也拒绝覆盖。WeakSet 只记录缺失存储／旧合成 revision 元数据，不缓存用户内容。首存、旧私有迁移、旧共享缺失 revision、公共 saveState 显式替换及合法备份恢复保持原语义。
- SharedStorage 无原子 CAS，不能消除最终 read→write 的跨进程窗口。防护仅拒绝已经观察到的冲突；快照失败、最终读取失败和冲突不写主状态，已写快照可保留。重要备份正常化未跳过，已接受写入不取消、不重试。
- 已存 reminderCalendarIDs 若显式非数组／null、含非字符串／空白／控制字符、超过 100 条或 512 字符，则 fail-closed 并进入检查，不扩大为全部列表。合法 []、旧缺失、trim／去重兼容，公开宽容 normalizer 不变。
- 新 `src/reminder_calendar_picker.tsx` 隔离权限、读取、选择与保存，增加 gate、generation／active 校验及 Calendar 只读 10 秒期限。授权弹窗不限时；离页后不启动迟到读取、更新 UI、弹提示或调用新保存。已调用 onChanged 仍一次完成，不误关闭后续页面。
- `app_refresh.ts` 进入后台取消 queued 0ms 工作并使旧回调失效；主页面 active／foreground 防护阻止退出后或后台开始新查询。恢复请求消费既有待刷新标志，期间新请求仍可排一个后续同步。

216 个符号定义、顺序、颜色、尺寸规则未改；不新增原生 API、字体、外部图库、定时服务或全局私密内容缓存。备注页、来源／ID／期次意图、缓存不可完成、只读、旧链接、备注隐私、250 ms 持久化兼容延时、4／10 秒提醒读取预算、30／5 分钟组件刷新请求保留。「立即更新」仍直接位于「查看提醒事项备注」下方。
