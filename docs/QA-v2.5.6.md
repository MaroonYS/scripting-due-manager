# v2.5.6 回归与验收

## 自动化验证

- 有效 Apple Reminder UUID 必须生成 `x-apple-reminderkit://REMCDReminder/{UUID}`，地址末尾不得附加 `/details`。
- UUID 校验应接受大小写十六进制、裸 UUID、`x-apple-reminder://{UUID}` 和已有的单项 reminderkit URL；任意额外路径／查询、缺段、非十六进制字符与空值必须被拒绝并回退到通用 `x-apple-reminderkit://`。
- 小、中、大组件的 Apple 提醒事项标题、备注／日期内容区必须使用对应事项自身的导航 URL。
- 小号顶部日期／类别与大号顶部摘要必须使用当前事项的同一 URL；中号通用标题仍打开到期管家。
- 小号底部下一事项预告必须使用下一事项自身的 ID，不得复用当前事项的 URL。
- 左侧类别图标必须继续位于 `Button + AppIntent` 完成控件内，不得因新增内容链接而变成导航链接；只读或缓存事项仍不得完成。
- 手动事项内容必须继续打开到期管家对应编辑页；组件错误状态继续打开检查页，不得被提醒事项 URL 覆盖。
- 组件内容链接不得改变完成识别码、事项排序、队列补位、排版尺寸、系统语言、图标推断、缓存格式或通知安排。
- 发布前运行完整测试、TypeScript 检查、`git diff --check`、安装包解压比对及云端发布检查，并在此记录最终测试数量与安装包 SHA-256。

本地结果：默认时区、UTC 与 America/Los_Angeles 各通过 234 项测试，0 失败；TypeScript 无诊断；`git diff --check` 通过；安装包完整且与源码逐文件一致。发布包 SHA-256：`ef68eff5fffb0e65e971f38f3185dbc5449f8c3f6d29467326e53a261024a0cc`。

## iPhone 必须验收

1. 在真实 iPhone 主屏幕分别放置小、中、大组件，并准备至少两个具有正常 UUID 的 Apple 提醒事项。
2. 分别点击当前事项的标题、List／备注、右侧日期，确认系统「提醒事项」打开且定位到该行对应的具体事项，而不是只打开通用首页。
3. 在小号组件点击底部下一事项预告的图标旁文字与日期，确认打开的是预告事项，不是当前事项。
4. 返回主屏幕后点击左侧类别图标，确认仍执行完成并由后续事项补位；内容区域的跳转不得误触发完成。
5. 在中、大组件逐行抽查，确认每一行标题与右侧信息均打开各自事项，邻近行不会串号。
6. 验证只读及离线缓存行：左侧图标保持不可完成；内容区若 ID 有效可尝试导航，无法定位时应能返回并在 Scripting 中核对。
7. 使用无法提取标准 UUID 的测试数据，确认内容区使用通用 `x-apple-reminderkit://` 打开系统「提醒事项」，不拼接具体事项路径，也不发生崩溃。
8. 核对 VoiceOver 焦点可区分“完成”和“打开事项”，并检查小、中、大组件原有字号、留白、日期、本地化及深浅色显示没有变化。

## 风险声明

- `x-apple-reminderkit` 是 Apple 未公开的内部 URL Scheme，不属于受支持的公开 API，模拟器或自动化测试通过不能证明真机可用。
- 本实现保持 `x-apple-reminderkit://REMCDReminder/{UUID}` 且不添加 `/details`；该后缀在部分 iOS 版本上有不兼容报告。
- 锁屏附件只显示总数，没有可选的单条事项，因此继续打开 Scripting；这不属于本次单项深链范围。
- 即使 UUID 格式正确，Apple 仍可能在任何 iOS 更新中调整或关闭该行为；每次系统升级后应重新执行上述真机验收。
- 此跳转只用于导航。完成 Apple 提醒事项仍通过原有 Scripting Reminder API 与交互式组件意图执行。

自动化测试不能替代 WidgetKit 真机跳转、原生排版、动画、VoiceOver 或真实通知送达验证。
