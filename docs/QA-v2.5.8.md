# v2.5.8 检测与修复记录

## 已确认并修复

1. **同步重试导航错误**：同步提示误用 widget-status。现在按错误来源区分入口，提醒同步进入自动刷新的主界面，完成异常进入操作结果页。
2. **缓存乱序与完成后回填**：旧查询可能晚于新查询或完成操作返回。加入查询起始时间、运行内顺序及共享失效标记；作废读取不能重写缓存，普通并发可采用更新的同范围结果。
3. **异步期间状态变更**：组件先读取手动状态再等待 EventKit，期间修改无法反映。新增 loadWidgetData 在返回后重新读取状态，列表变更时进行一次有界重试。
4. **离线查询范围失配**：原缓存只校验列表，未过滤缩短后的日期范围。现按请求范围筛选，全天事项以日初判断查询边界，定时事项使用实际时刻；不同长度查询不互相冒充完整结果。
5. **列表选择操作竞争**：选择页缺少同步提交锁，快速勾选依赖旧闭包。增加提交锁、保存时禁用控件、函数式多选更新及过期回调检查。
6. **无效日期污染持久数据**：周期推进至 10000 年会产生下次读取拒绝的日期。推进与写入前校验并抛错，原数据、快照和完成记录不变。
7. **早期年份偏移**：多参数 Date 构造函数对 0–99 年隐式加 1900。统一使用 FullYear 方法，覆盖闰年、跨世纪算术及组件本地化日期。

## 接口核对与限制

核对了 [Scripting Reminder 官方文档](https://scriptingapp.github.io/zh/guide/Device%20Capabilities/Reminder)：getIncompletes 支持 endDate 和 calendars，save 返回 Promise<void>，日期继续通过 dueDateComponents 读取。没有引入新的原生依赖。

共享 Storage 不提供跨进程原子比较写入。本版标记与写前复查改善已复现的异步交错，但无法保证所有原生并行执行窗口的事务隔离。实际 WidgetKit 刷新时机、点击动画、未公开的 Reminders 详情 URL 和通知送达仍需在用户的 iOS/Scripting 版本上验证。
