# 到期管家 for Scripting

紧凑原生风格的 iPhone 到期事项组件，支持信用卡账单、订阅、周期事项与 Apple 提醒事项。当前版本 **2.5.6** 将 Apple 提醒事项的组件内容区直接链接到系统「提醒事项」中的对应事项；左侧图标继续专门用于完成操作，现有布局、数据、语言、图标推断与通知保持不变。

周期可输入 1–99 的正整数，提前处理可设 0–365 天；两者在同一「重复」卡片，左侧始终有名称与单位。提前处理统一从提前日零点开始，未提前的定时事项按真实到期时刻处理，全天事项从到期日零点进入待处理且次日才逾期。月末及闰日锚点保持不变。只设置提前天数不会产生通知；要接收横幅，请另外开启「通知与提醒」。

## v2.5.6 的改进

- 小、中、大组件中的 Apple 提醒事项现在区分两种点击操作：左侧类别图标只负责完成，标题、备注／日期等内容区域则打开系统「提醒事项」中的对应事项；小号顶部日期／类别与大号顶部摘要也指向当前事项。
- 小号组件底部的下一事项预告也会打开预告所对应的 Apple 提醒事项，不会错误跳到当前事项；手动事项仍打开到期管家编辑页。
- 裸 UUID 和可确认的旧 URL 包装会统一生成 `x-apple-reminderkit://REMCDReminder/{UUID}`；本实现不附加在不同 iOS 版本上表现不一致的 `/details`。无法提取有效 UUID 时安全回退到通用 `x-apple-reminderkit://`，只打开系统「提醒事项」。
- 该跳转使用 Apple 未公开的 URL Scheme，不能承诺未来 iOS 版本永久兼容，发布前及系统升级后必须在 iPhone 真机验证。完成操作仍使用原有交互式按钮，不依赖这一 URL。

## v2.5.5 的修复

- 提醒标题中的明确品牌或具体事项始终拥有最高优先级；具体 List 分类以及 List 名中的品牌或产品信息也始终优先于备注。
- 备注中的品牌、产品或明确类别属于高置信度提示，可覆盖 `Tasks`、`Inbox`、`Personal`、`Reminders` 等通用 List；普通动作提示只在 List 完全没有命中时使用，避免含糊备注改掉可靠的 List 图标。
- 标题、List 与备注分别匹配，不会把分散在多个字段中的词拼接成不存在的品牌或类别。
- 提醒事项缓存快照只保存白名单内的图标提示及 `strong`／`ordinary` 置信度，不保存 Apple 提醒事项的备注正文、匹配词或文本片段。旧快照继续兼容；更新后运行一次主脚本完成实时同步，才能为旧提示补充置信度。
- 不改变小、中、大或锁屏组件的尺寸、排版、语言判断、点击行为和通知安排。

## v2.5.4 的修复

- `Card Setup`、`CARD—SETUP`、`VentureOne Bonus`、`Venture One Bonus` 及对应简繁体信用卡操作会从提醒标题识别为橙色信用卡图标。
- 完整 List 名 `Wallet Plan` 会作为信用卡分类后备；标题中的更具体类别仍优先。
- 不使用宽泛的单独 `card`、`wallet` 或“卡”匹配，并增加 `Cardinal`、`Venture Capital`、`Wallet Planning Workshop` 等负例保护。
- 继续保持标题、List 与备注分字段匹配，旧事项无需删除、重建或重新导入。

## v2.5.3 的修复

- 所有小、中、大及锁屏附件组件优先读取 `Device.systemLanguageTag`／`systemLanguageCode`，只有旧版 Scripting 未提供这些值时才退回 `Device.preferredLanguages`。
- 左上角图标语义名称、日期、内置标题、分区、空状态和错误提示共用这一语言来源。英文系统下，截图中的“税务会计”会显示为 “Tax & Accounting”。
- 明确选择简体或繁体中文时，脚本设置优先于地区推断；真实标题恰好为 “Untitled Reminder” 或“未命名提醒”时也会原样保留。
- 不迁移或重写任何事项，不改变组件尺寸、字号、行高、点击区域或通知安排。

## v2.5.1 的修复

- 通知按稳定事项身份匹配：文案变化逐条替换，未轮到的有效提醒继续保留；实际时刻变化优先修复已有排程。等待系统查询后及每次提交前重新校验当前时间，不把已过时间报告为未来待发。
- 主数据损坏时进入独立恢复页，不先启动普通主界面；恢复前隔离保存原始数据，保全失败不覆盖。未知更高格式禁止覆盖，可导出原始恢复档案。
- 恢复后，仅仍与完成记录精确匹配的事项保留安全撤销能力；异常大版本数字被拒绝，旧重复长 ID、关联通知开关及空白提醒标题能往返备份。
- Apple 提醒已完成后的缓存读写失败仅作为警告；缓存日期按当前时区更新。点「检查操作」直达结果说明页，也可在主界面进入「上次组件操作」。清除只作用于所查看的事件，不改变事项。

## 安全与提醒

- 「记录与数据安全」保留最近 100 条完成记录和 10 份本机快照。手动完成可安全撤销；后续已编辑、再次完成或删除的事项不会被覆盖。Apple 提醒事项须在系统 App 恢复。
- JSON 导出／导入包含手动事项、完成记录、显示设置和通知偏好；严格校验并在恢复前保存快照。恢复后通知先关闭，请核对后重新开启。超过 1,000 条事项不再被静默截断。
- 本地通知默认关闭，仅处理手动事项，可设提醒时间、到期日再提醒和单项关闭。滚动安排未来 90 天、最多 40 个提醒计划；组件普通新增或文案更新每次最多 3 条，已有提醒的实际时刻修复最多 40 条。逐条替换先确认新请求，再移除旧请求，瞬间可能保留 1 个替换副本；宿主总请求保守限制为 60。无替换余量或系统接口失败时保留旧请求并显示未完成状态，请打开主脚本重试。不保证无限期后台运行或准点横幅。
- 同步失败时显示最后成功读取时间及重试指引。更新页显示当前／最新版本和更新内容；手动安装前创建快照，并使用已核验的版本化资源，拒绝重复安装和降级。
- 本机快照仍在同一设备内，不能代替独立备份；导出的文件包含名称、金额和备注，请保存在可信位置。

详细更新内容见 [发行说明](./RELEASE_NOTES.md)，真机待验收范围见 [QA 清单](./docs/QA-v2.5.6.md)。自动化测试不等于真机跳转、排版、动画或通知送达验证。

现有组件排版保持不变：小号金额与备注继续左对齐；中、大号的金额和备注继续使用固定 116/124 pt 右栏与单行槽位，过长时先使用系统字距收紧，最低保持 85% 字号，再从中间省略以同时保留首尾信息。该策略不会改变标题宽度、组件容量、行高或完成图标点击区。所有组件文案优先读取 iPhone 系统语言，在简体中文、繁体中文和英文之间自动切换，其他语言使用英文兜底；日期始终按系统语言标记的完整地区格式显示。小号左上角仅保留当前图标的本地化语义名称，不再重复显示图标；当前事项图标仍是 17 pt 完成按钮，点击热区保持 40 pt，主体标题继续按实际宽度使用 16/15/14 pt 适配一、二、三行。小、中、大组件不显示“明天”“2 天后”“逾期 6 天”或 24 小时实时倒计时，只显示明确的本地化日期；小号底部预告同步显示下一事项日期。中号保持 17 pt 图标、38 pt 点击热区、2–3 项动态容量及无分隔线布局；大号保持 18 pt 行图标、40 pt 点击热区、26 pt 摘要图标，并按实际高度显示 3–5 项。中、大号标题最多两行。左侧事项图标只用于完成；手动事项的文字内容打开到期管家编辑页，Apple 提醒事项的标题、备注／日期以及小号下一事项预告会尝试直达系统对应提醒；小号顶部日期／类别和大号顶部摘要也指向当前事项。只读或缓存事项的图标会变灰，右侧保留绝对日期及锁定或缓存标识。大号继续使用系统「提醒事项」风格的摘要、分区和留白节奏，完成后由后续事项补位。交互后的内容更新时间仍由 WidgetKit 决定，不声称使用 Apple 私有的点击瞬时动画。Apple 提醒事项的详情跳转使用未公开的 `x-apple-reminderkit` URL Scheme；无法提取有效 UUID 时回退到通用 `x-apple-reminderkit://` 并打开系统「提醒事项」，且此能力需要真机持续验证。锁屏附件只显示总数，没有单条事项链接，继续打开 Scripting。Apple 提醒事项可按一个或多个具体列表筛选；图标离线分层推断：事项标题始终优先，随后是具体 List 分类及 List 名中的品牌或产品，高置信度备注可覆盖通用 List，普通动作备注只在 List 未命中时使用，最后才回退默认值。规则覆盖 126 个 List 图标方向与 1,100+ 个简体、繁体和英文别名；缓存只写入白名单图标提示及 `strong`／`ordinary` 置信度，不写入备注正文。手动事项提供 11 种到期类型，并内置 130 个本机 SF Symbols。

## 一键安装或更新

[在 iPhone 上安装或更新到期管家](https://www.scripting.fun/import_scripts/?urls=%5B%22https%3A%2F%2Fgithub.com%2FMaroonYS%2Fscripting-due-manager%2Freleases%2Flatest%2Fdownload%2Fdue-manager.scripting%22%5D)

固定链接始终指向 GitHub 最新发行版。安装后，脚本还会通过 `remoteResource` 使用同一地址检查更新；主脚本底部的「检查并更新版本」会先检查 GitHub 的正式版本和安装包，再显示更新说明，安装前保存快照并生成新的下载请求。发布流水线逐文件校验安装包与源码，不允许以不同内容覆盖已有版本。

从 1.2.0 升级时先不要删除手机里的旧脚本；让现有脚本更新到最新版后运行一次，它会把旧事项迁移到本机持久域。2.4.0 可兼容读取 schema v1/v2 数据，旧事项的提前天数默认为 0，并在下次保存时写为 schema v3；无需重新添加事项或桌面组件。

完整功能说明和安装要求见 [`到期管家/README.md`](./到期管家/README.md)。
